# Methodology Decisions and Issue Log

This file records pipeline issues found during pilot runs and the changes made
to reduce bias, improve ranking quality, and make later methodological reporting
auditable.

## Current Scope

- The first-pass cheap-model ensemble is for inexpensive recall into a
  shortlist, not final ordering.
- The second-pass GPT-5.4 ranker is a high-recall comparative ordering stage,
  not the final headline ranking.
- The accepted-50 reference now uses PDF-aware frontier judge cards from GPT-5.5
  xhigh, GPT-5.4 high, and Claude Opus 4.7 high. Each card sees the configured
  first-page PDF excerpt plus extracted main-paper text. A GPT-5.5 xhigh
  all-pairs tournament over the synthesis top 30 is the current gold ordering
  for top-rank evaluation.
- Retrieval is disabled in the implemented pipeline: no web search, file search,
  vector store, or external tool list is passed to the model calls.

## Contribution Classes

Each paper should receive one primary class and optional secondary classes:

- `core_ml_algorithm`: new modeling, optimization, inference, or learning method.
- `theory`: formal analysis, guarantees, or conceptual theory.
- `benchmark_dataset`: benchmark, dataset, protocol, or evaluation resource.
- `infrastructure_systems`: systems, compilers, training infrastructure, tooling.
- `scientific_modeling_tool`: ML method primarily enabling empirical science,
  simulation, measurement, or discovery.
- `safety_governance_eval`: safety, alignment, governance, policy, auditing, or
  eval work.
- `application_method`: domain-targeted method whose main claim is practical
  performance in a specific application area.
- `analysis_position`: empirical analysis, synthesis, interpretability, or
  position-style contribution.

Overall ranking should remain a single list for "best overall contributions,"
but reported analyses should also include category-specific leaderboards. This
is cleaner than forcing datasets, infrastructure, and scientific tools to
compete only as if they were new algorithms.

## Ranking Principle

First-pass models should answer: "Is this worth sending to the expensive
strong-model/human review stage?" They should not be trusted to identify the
final best papers by absolute 1-10 scores.

Second-pass models should answer: "Among shortlisted papers, which have the
strongest evidence-grounded case for broad scientific or ML-field impact?"

## Evaluation Principle

Do not judge the cheap first-pass stage by whether its local ranks look
reasonable in isolation. Judge it by recall: does it preserve the papers that a
stronger reference judge would rank highly? This is especially important for
batch ranking because local competition can suppress strong papers if too few
papers advance from each batch.

For subset candidate files, rank correlation should be interpreted only as
relative ordering among shared papers. Top-k recall is the primary metric for
whether a cheap stage is good enough to feed the expensive stage.
